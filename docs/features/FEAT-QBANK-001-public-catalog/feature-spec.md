# FEAT-QBANK-001 若依版本化面试题库 Feature Spec（V2）

> 文档状态：Draft（Canonical Feature Spec 尚未 Approved）  
> 风险等级：L3  
> 当前阶段：7 开发实现  
> 证据结果：NotRun

## 1. 目标与非目标

### 1.1 目标

在若依统一身份和权限体系下，提供一个可治理的面试题库：

- 匿名或登录用户可以读取已发布题目，按模块、关键词、难度和游标分页浏览；
- 登录用户可以保存自己的答案覆盖，不修改公共标准答案；
- 题库编辑角色可以创建草稿、新建不可变版本、维护 Rubric 并提交审核；
- 题库审核角色可以驳回、发布和下线，并留下审计事实；
- 同一公共题目在 Portal 和 Admin 中引用稳定的题目版本，避免发布时静默改变正在进行的面试。

### 1.2 非目标

本 Feature 不包含：

- 普通用户创建或直接发布公共题目；
- AI 批量生成题目、社区投稿、收藏、练习计划、评分报告或支付权益；
- 移动原生 App；H5 由 `portal-web` 承担；
- 旧项目身份、Cookie、API 或独立 Spring Boot 入口兼容。

## 2. 用户与权限

| 角色 | 允许动作 | 禁止动作 |
|---|---|---|
| 匿名用户 | `GET /api/v1/questions`、`GET /api/v1/questions/{id}` | 任意写入、查看草稿或个人答案 |
| 登录用户 | 公开读取、保存/更新自己的个人答案 | 创建公共题目、读取他人答案、绕过租户边界 |
| 题库编辑 | Admin 草稿、新版本、Rubric、提交审核 | 发布、下线（除非同时拥有审核权限） |
| 题库审核 | 审核、驳回、发布、下线、查看治理快照 | 修改不属于授权租户的题目 |
| 系统管理员 | RuoYi 用户/角色/菜单及审计查询 | 通过前端伪造业务主体或跳过审计 |

所有登录写操作从 RuoYi JWT 解析出的 principal 获取 `userId`、角色和租户；不得信任请求体中的用户、角色或租户字段。公开 GET 不应因为缺少 JWT 而触发登录态清除。

## 3. 业务规则

- `BR-QBANK-01` 公开查询只返回当前已发布指针指向的版本；草稿、审核中和已下线版本不可匿名读取。
- `BR-QBANK-02` 公开详情必须包含题目 ID、不可变版本 ID、版本号和内容；不得返回仅供治理使用的内部来源凭据或草稿字段。
- `BR-QBANK-03` 题目版本和 Rubric 版本不可原地修改；修改必须创建新版本并保留历史版本。
- `BR-QBANK-04` 题库编辑/审核接口使用 RuoYi JWT + RBAC；权限拒绝统一返回 401/403，不降级为成功或 `CAPABILITY_UNAVAILABLE`。
- `BR-QBANK-05` 普通用户不能调用公共题目创建接口；Portal 不展示该入口。公共内容只能走 `/admin/questions` 工作流。
- `BR-QBANK-06` 个人答案按 `(publicTenantId, userTenantId, userId, questionId)` 隔离并加密保存；读取和写入均校验资源归属。
- `BR-QBANK-07` 个人答案覆盖只影响当前登录用户的阅读投影；公共标准答案和已发布版本不被覆盖。
- `BR-QBANK-08` Admin 写命令必须带 `Idempotency-Key`；重复请求返回同一业务结果，不重复创建版本或审计事件。
- `BR-QBANK-09` 版本敏感操作必须带 `If-Match: "vN"`；版本不一致返回 409，并要求重新读取快照。
- `BR-QBANK-10` 合法工作流为 `DRAFT -> IN_REVIEW -> PUBLISHED -> RETIRED`；已有发布版本时允许 `PUBLISHED_WITH_DRAFT`/`PUBLISHED_WITH_REVIEW`，不得跳过审核直接发布。
- `BR-QBANK-11` 驳回、发布、下线必须记录操作者、原因码、目标版本和时间；错误响应不得泄露答案正文或跨租户数据。
- `BR-QBANK-12` 未启用业务存储或配置不完整时 fail-closed，返回稳定错误；不得拼造成功 DTO。

## 4. 功能需求（REQ）

- `REQ-QBANK-01`：公开题目列表支持模块、关键词、难度和游标分页。
- `REQ-QBANK-02`：公开详情读取已发布版本和标准答案，提供稳定版本元数据。
- `REQ-QBANK-03`：登录用户保存和更新个人答案，支持查看自己的答案与系统答案切换。
- `REQ-QBANK-04`：题库编辑创建草稿、不可变内容版本和 Rubric 版本。
- `REQ-QBANK-05`：题库审核执行提交审核、驳回、发布、下线及审计。
- `REQ-QBANK-06`：Admin API 提供状态筛选、详情快照、ETag/`If-Match` 和幂等语义。
- `REQ-QBANK-07`：Portal、Admin 和后端共享同一 RuoYi JWT/RBAC 契约，不引入第二套登录态。

## 5. 验收条件（AC）

- `AC-QBANK-01`：匿名请求公开列表和详情成功；匿名请求任何写接口均被拒绝，且已有登录态不会因公开 GET 失败而清除。
- `AC-QBANK-02`：12 个固定模块的发布数据、搜索、难度筛选、游标分页和版本引用可稳定回读。
- `AC-QBANK-03`：详情只返回当前发布版本和允许公开的答案字段，不返回草稿、内部来源凭据或其他用户答案。
- `AC-QBANK-04`：登录用户可保存个人答案；答案按用户/租户隔离，公共标准答案保持不变。
- `AC-QBANK-05`：编辑角色可完成草稿→新版本→Rubric→提交审核；缺少权限、主体或必填字段时明确失败。
- `AC-QBANK-06`：审核角色可驳回、发布和下线；非法状态转换、跨租户访问、错误 `If-Match` 均返回可识别的 4xx。
- `AC-QBANK-07`：相同 `Idempotency-Key` 重试不重复创建版本、发布事实或审计事件。
- `AC-QBANK-08`：Portal 不存在普通用户“添加公共题目”入口；Admin 工作台展示加载、空态、错误、权限拒绝和冲突恢复状态。
- `AC-QBANK-09`：旧版题库的“公共新增题目”证据明确标记为 Superseded，不被计入 V2 的 EV/UAT 通过结论。

## 6. 错误与恢复

| 场景 | 结果 | 客户端动作 |
|---|---|---|
| 未登录访问公开 GET | 200/404（按资源状态） | 保持匿名浏览 |
| 写操作 401/403 | 稳定错误 envelope | 不清除无关页面状态；按权限提示 |
| 版本冲突 409 | 返回当前版本/关联信息，不返回敏感正文 | 重新读取并让用户确认覆盖 |
| 幂等键重放 | 返回第一次结果或明确冲突 | 不重复提交 |
| 网络/5xx | `retryable=true` | 保留编辑草稿，允许重试 |
| 题目已下线/不存在 | 404 或稳定业务错误 | 从详情返回列表，不伪造内容 |

## 7. 实施与证据边界

当前文档仍为 Draft。代码实现可在已批准的本地执行包内进行，但构建、测试、启动、真实数据库、浏览器 UAT、发布和 Git 均需独立授权；代码存在不等于 AC 通过。

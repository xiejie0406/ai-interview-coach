## 1. 调研目标

本轮调研服务于三个待讨论项目：生产排程系统、Aden Agent 桌面智能执行平台、AI 服装智能搭配与报价系统。目标不是照搬竞品功能，而是先回答以下问题：

1. 市场已经把问题拆成哪些产品类别，各自服务什么客户和场景。
2. 代表产品采用怎样的用户流程、业务规则、数据结构和执行逻辑。
3. 哪些能力已经成为行业基线，哪些仍是差异化能力或宣传性能力。
4. 三份现有 PRD 的范围是否过大、顺序是否合理、最危险的假设是什么。
5. 下一步讨论和页面原型应优先验证哪些产品决定。

## 3. 横向结论

| 项目 | 市场本质 | 行业主流逻辑 | 当前最大风险 | 制作原型前首要决定 |
| --- | --- | --- | --- | --- |
| 生产排程 | 不是单一排程器，而是 ERP/SCM/MOM 套件 APS、专业 APS、轻量云制造和 AI 协同等不同路线 | 取数与校验 → 有限产能求解 → 人工审查/修复 → 发布 → 现场反馈 → 受控重排 | 未确定首个行业模板、排程粒度、系统边界和 ERP/MES 事实源；一期范围接近中高阶 APS/MOM | 首个目标行业与客户、P0 排程对象、必须满足的约束、正式计划发布边界 |
| 桌面 Agent | Computer Use 模型、通用任务 Agent、企业 RPA/APA 和开源执行框架的组合市场 | Agent 负责判断，确定性策略控制权限，API/连接器优先执行，GUI 作为降级，并以持久任务状态、人工审批和证据包闭环 | 1688 商业授权路径与个人微信自动化边界未通过验证；外部副作用还涉及幂等、恢复和审计 | 一期只走哪些正式授权通道；采购或客服哪条先做；个人微信是否暂时排除 |
| AI 服装搭配与报价 | 商品理解、搭配推荐、视觉/VTO、B2B 目录订货和 PLM/BOM/RFQ 五层能力的组合市场 | 硬条件过滤 → 商品池召回 → 兼容性排序 → 业务规则重排 → 人工确认；视觉生成与 SKU/库存/价格事实分离 | 首批付费客户和“报价”语义未定；销售报价与生产成本报价是两套不同模型 | 先确定客户类型、销售报价或成本报价、一期是否只用真实商品图而后置 VTO |

三条路线都不建议先把竞品功能合并成一份大而全的设计。更稳妥的共同顺序是：先确认首批客户和单条主闭环，再定义业务对象、状态、权限与失败恢复，随后制作可点击页面原型，最后才冻结详细设计范围。

## 4. 证据规则

- **官方事实**：来自厂商产品页、产品文档、发布说明、官方案例、公开论文或其他一手资料，并附访问链接和适用边界。
- **分析推断**：依据多个事实做出的产品或技术判断，必须显式标明为分析，不冒充厂商承诺。
- **待验证假设**：需要客户访谈、现场数据、试用、技术验证或商务询价才能确认的内容。
- 易变信息以 2026-09-10 为检索基准；没有公开价格、部署细节或效果数据时记录为“未公开”，不猜测。
- 竞品能力不自动转化为本项目需求；产品范围、优先级和取舍留待后续讨论决定。

## 5. 建议讨论顺序

每个项目按同一顺序评审：

1. 确认目标客户、使用者和第一条必须跑通的业务闭环。
2. 从竞品共性中识别必须具备的行业基线。
3. 从竞品限制和实施难点中确定一期明确不做的范围。
4. 选择一至两个可验证的差异化方向。
5. 把结论转成需求边界、关键状态和页面原型验证清单。

本轮调研完成不代表需求、设计或技术方案已批准，也不代表任何竞品能力已经在本项目中实现或验证。

# 本机可试用演示版本

> 文档类型：项目开发记录；状态：本机已验证；日期：2026-09-26  
> 授权依据：用户要求直接可测试的版本，并授权生成测试数据。

## 目标与验收

- 在现有 `ry-vue` 和本机 `127.0.0.1` 服务上准备带 `DEMO` 标识的商品、库存、客户、方案和 Agent 版本，无需用户手工配置内部版本。
- 本机 Python Runtime 显式启用 `demo` 模式后，需求分析、商品属性建议与冻结候选搭配返回结构化演示结果，经过原有认证、契约和 Java 校验链路；默认 `disabled` 模式保持原行为。
- 从管理端创建需求分析与搭配 Run，页面能展示演示结果，并在人工确认后写回演示方案；不触发外部模型、图片 Provider 或真实费用。

## 边界与实施

风险等级 L2：新增本机演示行为，但只在显式配置下启用，数据带独立标识且可辨认。保留 Java/MySQL 为业务权威，Python 不连接 MySQL。先备份当前本机数据库；写入只针对独立 DEMO 标识，遇到冲突停止，不覆盖现有记录。新增 Python 演示适配器和最小验证，配置本机进程，生成幂等样本脚本，重启本机服务并做浏览器验收。无法代表真实模型质量或正式 UAT。

失败时停止演示 Worker，恢复 `FASHION_AI_PROVIDER_MODE=disabled`，并保留演示数据供核查；需要删除样本时另按实际引用关系处理，不直接覆盖整个共享库。

## 本机入口与测试方法

- 前端：`http://127.0.0.1:5173/fashion/workbench?quoteId=980000000601`，当前若依管理员会话可以直接打开。
- 演示方案：`DEMO-LOCAL-001`，客户为 `【演示】晨光公司`，4 款演示商品及库存。演示图片为本机生成的简单图形。
- 页面步骤：载入方案 → 开始分析 → 采用需求 → 生成搭配 → 采用全部候选组合。已完成的示例可直接浏览搭配结果；要重新体验 Run，可再次从“开始分析”执行。
- Python 本机使用 `FASHION_AI_PROVIDER_MODE=demo`；现有 Java/Python 共享 HMAC 密钥保存在 Git 忽略的 `.env`，无需用户手工填写。模式仅适用于本机演示；默认仍为 `disabled`。

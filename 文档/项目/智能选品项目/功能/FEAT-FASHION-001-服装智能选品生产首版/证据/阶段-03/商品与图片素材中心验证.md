## 1. 实现范围

- Java 新增 SKU 粒度商品领域、查询、详情、手工新增、批量编辑、上下架、属性与图片确认能力，继续只使用 `fq_product`，未拆回 SPU、颜色款或独立图片主表。
- 商品导入使用 `fq_import_batch`、`fq_import_detail` 留存预览、发布、冲突和逐行结果；普通商品资料导入不写当前价格或库存。
- CSV 与 XLSX 解析采用有界流式读取；XLSX 使用 POI SAX 事件模型，不把完整工作簿加载为对象图。
- 图片素材上传执行文件类型、magic、大小、像素、对象键、重复内容和映射校验；确认时按来源、款号、颜色准确关联，并通过公共 catalog-write 锁和 `row_version` 防止错写。
- Admin 新增商品运营、商品资料导入和图片素材三个页面及对应 Java API 类型；覆盖加载、空态、行级错误、预览、发布、局部编辑、状态切换、图片预览与确认。
- RuoYi 菜单和权限脚本新增商品、导入、素材入口及操作权限，但未向任何角色自动授权。

## 3. 隔离 MySQL 结果

最终场景在临时 MySQL 8.0.46 上完成迁移并验证：

- `products=3`，同款黑白两个颜色商品并存，黑色图片没有关联到白色商品；
- `stock_rows=0`、`stock_pollution=0`，证明普通商品资料导入未污染库存；
- 商品有效发布批次 `success_product=1`，图片有效确认批次 `success_image=2`；
- 损坏文件与缺失映射产生 `invalid_image=2`，未写入商品图片；
- 并发版本变化产生 `conflict=1`，冲突批次留痕且未覆盖较新数据；
- 重复预览、重复发布、重复图片确认均保持幂等；CSV 中款号 `000123` 保留前导零。

临时测试实例完成后已经停止，精确的 `.codex-tmp/fashion-mysql-imp03-*` 测试目录已移入 Windows 回收站；系统中原有 MySQL 进程未被修改或停止。

## 4. 发现与修正

| 发现 | 修正 |
| --- | --- |
| 图片确认误用商品导入批次字段，可能覆盖商品资料导入血缘 | 图片更新不再写 `last_product_import_batch_id` |
| `Instant` 在真实 MySQL 场景的 JSON 序列化缺少 JSR-310 支持 | 增加 `jackson-datatype-jsr310` 并以真实数据库回归 |
| XLSX 初版使用整本工作簿对象解析 | 改为 POI SAX 事件流，并增加多 Sheet、公式和数值编码拒绝测试 |
| 有损 WebP 的 `VP8 ` 尺寸未识别 | 上传策略同时支持 VP8X、VP8L 和 `VP8 ` |
| 示例 CSV 的来源值不属于平台字典 | 改为 `MANUAL`，并用脚本测试锁定样例与字典一致性 |
| 浏览器素材页缺少可见预览和服务端像素信息 | 增加本地缩略图、服务端识别像素和对象 URL 回收 |
| Playwright 首轮严格选择器命中多个“在售”文本 | 选择器收敛到商品表格范围后重跑通过 |

## 5. 依赖、限制与后续

- 新增运行依赖：Apache Commons CSV 1.14.1、Jackson JSR-310；XLSX 继续复用工程已有 Apache POI。
- 本阶段没有启用 Python Provider，没有向浏览器暴露 Python 地址、服务密钥或 Provider Secret，也没有创建独立价格、库存、SPU、颜色款、SKU、图片任务或审核表。
- Docker 在当前环境不可用，因此 Testcontainers 条件测试默认跳过；核心数据库路径已经用独立启动的真实 MySQL 8.0.46 补充验证。
- 本阶段没有执行新的全量依赖漏洞审计；IMP-01 已完成的依赖审计结论不自动覆盖本阶段新增依赖，生产候选阶段必须重新执行。
- REQ 01、REQ 04 的实现与 AC 01、AC 05 自动化场景可作为 IMP-03 退出门证据；正式业务 UAT 仍为 NotStarted，真实京东授权页面下载试点留在 IMP-10 候选环境验证。

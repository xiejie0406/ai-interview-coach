## 1. 实现范围

- Java 实现客户查询、新建、修改、归属/协作者访问和归档；联系人手机号使用独立外部密钥 AES-256-GCM 加密，未配置密钥时非空手机号拒绝写入，不降级明文。
- 方案实现草稿新建、修改、复制、关闭、客户切换和访问恢复；客户切换会清除旧需求确认与价格事实，缺少当前有效价格时明确阻断后续正式流程。
- Agent 与不可变版本实现创建、发布和当前版本定位；Conversation、Message、Run、Run Step 均只写 Java/MySQL 六张既有 AI 表，没有增加第 17 张 `fq_*` 表。
- 进程内 Worker 实现领取事务、租约续期、过期接管、fencing、取消确认、deadline、有限重试、幂等和终态提交；Runtime 网络调用发生在领取事务提交之后。
- Java 到 Python 只发送冻结、带版本的最小上下文；HMAC、request/correlation ID 和 W3C Trace Context 延续 IMP-01 契约。Run 可按 correlation ID 查询，生命周期记录排队、运行、失败、接管和超时低基数指标。
- Python 增加需求分析和商品属性建议的严格 typed output 用例。商品建议只允许品类、颜色、季节、风格、场景、人群和可观察外观标签；品牌、面料、尺码、价格、库存、客户信息和正式采用事实不在输出权限内。
- Admin 增加客户中心、方案管理、方案工作台、Agent 版本页及商品属性建议弹窗；建议与确认值分离，只有操作人点击采用才由 Java 在公共 catalog-write 锁和 `row_version` 条件下写商品事实。
- Provider 未配置时 Java 能力接口和 Admin 均明确显示 disabled，Python 返回 `503 PROVIDER_DISABLED`，没有样例结果、规则结果或伪造 Provider 记录。

## 3. 关键业务证据

- 客户手机号在 `fq_customer.contact_phone` 中保存为 `v1.{keyId}.*` 密文，明文不落库；同一客户只对负责人、协作者或管理员可见。
- “采购 100 套、1～4 个递进品类档位、每档 3 个候选、每套不超过 300 元”经 typed analyzer 测试分别落到 `set_count=100`、四个 `category_tiers`、每档 `candidate_count=3` 和 `per_set.maximum_minor=30000`，没有混成一个字段。
- 商品属性输出不能携带品牌、面料、价格、库存或客户字段；Java 即使收到额外不可采用字段也不会把它映射为商品事实。
- 商品属性 Run 成功后仍为 `not_applied`；人工采用事务写入确认标签、`attributes_confirmed`、确认人/时间和 `last_ai_run_id`，并受商品 `row_version` 与公共 catalog-write 锁保护。
- 需求 Run 的首次领取、续租、租约过期由第二 Worker 接管、旧 fencing token 完成被拒绝、新 token 完成成功均在真实 MySQL 验证；取消中的任务由 Worker 确认为 `cancelled`，到期任务转为失败。
- 相同 request key 的不同输入摘要返回冲突；运行固定 Agent 版本和配置哈希，发布新版本不会改写旧 Run。
- 客户切换、报价草稿和 Run 详情均在服务端重验客户访问权；前端状态不作为权限真相。

## 4. 执行中发现与修正

| 发现 | 修正 |
| --- | --- |
| 客户手机号最初直接对应数据库文本列，违反联系人敏感字段边界 | 增加独立 AES-GCM cipher 与外部 key ring；未配置时拒绝非空写入，并加入密文/解密测试 |
| Run Step 插入值数量与列数量不一致 | 修正 INSERT，占位和值与 T16 精确字段对齐 |
| 助手消息查询使用不存在的 `conversation_id` 来源 | 改为读取实际 Conversation 主键，隔离 MySQL 验证通过 |
| 商品 ID 在 JSON 快照中按稳定字符串传输，领取代码只接受数值节点 | 同时接受正整数 JSON number 和 1～19 位稳定字符串；需求 Run 的空商品 ID 不再触发装箱 NPE |
| 初版商品建议允许品牌和面料，可能把不可观察事实误当确认值 | 契约和 Java 采用白名单改为品类、颜色、季节及确认标签；品牌、面料、尺码、价格和库存全部排除 |
| trace 注入头常量大小写拼写不一致会在真实 adapter 构造请求时取到空值 | 统一使用 `FashionTelemetryHeaders` 常量，保留 no-op OTel 时的合法 `traceparent` fallback |
| 首次 Playwright 全套对模型文案期望为 `test-provider`，模拟响应实际为 `openai` | 将断言对齐同一模拟事实，完整 4/4 重跑通过 |

两轮隔离 MySQL 修正过程中的失败分别为“商品 ID 未解析”和测试自身传入了超长未哈希 `apply_input_hash`；均保留为失败事实并修正后从全新数据库重跑。最终临时 MySQL 正常停止，精确测试目录移入 Windows 回收站；工作区既有 MySQL 未修改或停止。

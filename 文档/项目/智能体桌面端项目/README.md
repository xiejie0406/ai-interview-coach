# 智能体桌面端项目（Aden）

> 文档类型：独立项目控制入口  
> ID：PROJ-ADEN-002；版本：3.12.0；文档状态：Approved  
> owner：用户负责产品方向与高风险授权；Codex 维护本轮文档事实  
> 创建日期：2026-09-11；更新日期：2026-09-13  
> 当前阶段：FEAT-ADEN-001 Stage 8 审查验证已完成；下一阶段：Stage 9 用户验收  
> 风险：完整产品为 L3；当前仅含合成数据的桌面执行底座切片为 L2  
> 授权边界：未授权真实账号、真实业务数据、对外发送、网站采集、部署、发布或 Git 写操作

本项目建设一套中心控制面和 Windows 桌面执行底座，面向个人微信客服、采购询价和电商信息采集三个能力包。三个能力包必须独立授权、独立验证、独立停用；任何原型、代码骨架或纸面设计都不能自动升级为生产能力。

## 1. 当前状态

| 模块 | 当前实现事实 | 当前验证事实 | 下一门禁 |
| --- | --- | --- | --- |
| CORE 共用底座 | IMP-01～10 已完成：机器契约、MySQL / Java 控制面、Runner simulator、可恢复 SSE、Python Agent 离线 Fake、Electron 安全壳与 renderer Task Center 已贯通 | Java 554、MySQL 20、Runner 28、Agent 31、Desktop 55 项测试，契约门、18 模块干净构建、三入口 bundle、实窗 smoke 与真实本地合成 E2E 通过 | Stage 9 用户验收；人工 captcha-enabled 路径待执行 |
| WX 个人微信客服 | 未实现 | NotRun | 明确真实范围、数据处理和 UIA 测试条件后，另行按 L3 审查 |
| PUR 采购询价 | 已有本地交互原型；未形成生产连接器 | 原型验证记录保留既有合成数据结果；不等同于生产验证 | 补齐生产任务、金标与故障集，再进入平台和 Runner 集成 |
| COL 电商信息采集 | 未实现 | NotRun | 明确来源授权并建立只读采集金标集 |

当前实现路线以 RuoYi / Spring Boot 为唯一服务端控制面，以 MySQL `aden_*` 表族承载项目业务事实，以 Electron + Vue 作为桌面壳；Python 拆为低权限 `aden-agent-runtime` 和独立 `aden-runner`，不形成第二套任务、审批或审计真相。目标态按源码组织为 4 个实现单元：随现有 `ruoyi-admin` 运行的 `ruoyi-aden` Maven 模块、`aden-desktop`、两个彼此隔离的 Python 工程；另有 1 个 `contracts/aden/` 机器契约目录。运行时对应 `ruoyi-admin` JVM、Electron、Agent Worker、Runner 四类组件。该边界由桌面执行底座的[总技术设计](功能/FEAT-ADEN-001-桌面执行底座/技术设计.md)与[ADR-ADEN-001](决策/ADR-ADEN-001-工程与安全边界决策.md)共同记录。

此前的 Python-first / FastAPI / Temporal 中心控制面方案已经失效，只保留为[历史架构候选](归档/架构/基于Python的多智能体架构候选.md)供追溯，不是当前设计或实施依据。

## 4. 实施与风险边界

- RuoYi 是唯一服务端控制面；不得另建 FastAPI 业务后端或让 Python 持有业务终态。
- 真实微信 UIA 试验只能在固定版本、专用测试机、明确测试对象和停止条件下另行开展。
- 电商采集遇到拒绝、验证码、账号限制或权限不明时必须停止，不实施反检测或平台限制规避。
- 对外发送、付款、下单、接受报价等真实副作用必须经过明确授权、确定性策略和可审计回执。
- 用户验收尚未发生；上线就绪为 `NotAssessed`；发布为 `NotReleased`。

## 1. 问题与目标

现有 Aden 材料已经描述 WX、PUR、COL 三个能力包及完整安全目标，但此前技术稿把 FastAPI / Temporal Python 写成中心控制面，与用户本轮“后端采用 RuoYi”的明确决定冲突；仓库虽已有 Aden Java / Electron 工程骨架，却没有已验证的完整服务端与桌面业务闭环。若直接同时开发三个连接器，会在任务真相、权限、审批、外部动作重试和验证范围尚未闭合时放大风险。

本 Feature 的目标是先建立一个不接真实外部系统的公共底座，让后续每个能力包复用同一任务、权限、证据和恢复语义。成功标准不是“页面存在”，而是合成任务能由 RuoYi 权威推进，桌面端能恢复展示，Runner 模拟器能在重复、断线、超时和取消条件下给出可解释结果。

## 2. 范围与非目标

### 2.1 本切片范围

- RuoYi `ruoyi-aden` 业务模块、工作空间边界、任务状态机、任务 API、幂等和乐观并发。
- MySQL `aden_*` 基础表、事务 Outbox / Inbox、Runner 注册 / 会话 / delivery / 回执的持久化边界。
- Electron/Vue 桌面壳在本地合成 RuoYi 环境中的 captcha 开 / 关、登录、登出与会话失效处理，以及任务列表、状态详情、连接状态和安全运行时边界；不使用生产或第三方真实账号。
- 无权限 Runner 模拟器，以及 REST 快照 + SSE 进度的合成端到端闭环。
- 与 Runner 分离的 `aden-agent-runtime` 离线 Fake 骨架；只验证强类型候选、生命周期和安全停止，不接服务端 AgentJob 运行链。
- 断线、重复、失租、取消、过期和未知结果的故障测试。

### 2.2 非目标

- 不实现或测试个人微信 UIA、真实电商页面、ERP、真实供应商会话或外部发送；不实现、启用或调用真实模型 Provider。
- 不做自动下单、付款、签约、接受报价、验证码处理、反检测、代理轮换或平台限制规避。
- 不在首版引入 Temporal、Kafka、NATS、Redis Streams 等第二套流程真相或路由背板。
- 不承诺安装包签名、自动升级、生产高可用、SLA、用户验收或发布。

## 4. 业务规则

- BR-01：任务状态只由 RuoYi 命令处理器按 `state × actor × command` 推进。公开 OperatorCommand 当前只含提交校验和请求取消；Runner 只交 receipt，由服务端 adapter 产生内部命令。桌面端、Runner、Agent、SSE、操作员伪造的内部命令或数据库脚本都不能直接宣告业务终态。
- BR-02：最小状态为 `DRAFT → VALIDATING → QUEUED → RUNNING → SUCCEEDED`；等待分别使用 `WAITING_USER`、`WAITING_EXTERNAL`；失败为 `FAILED`。
- BR-03：取消请求先进入 `CANCEL_REQUESTED`。只有 Runner 或协调器证明到达安全点后才能进入 `CANCELED`；取消请优先于租约到期重试，该状态下不得 requeue 或创建新 attempt。无法确认的在途动作保持 Task `CANCEL_REQUESTED`并将 Delivery 标为 `OUTCOME_UNKNOWN`，不能伪装成已取消。
- BR-04：终态不可恢复或重复完成。需要重做时建立新任务或明确的新尝试，不改写旧终态。
- BR-05：相同幂等键与相同请求 hash 返回原结果；相同键不同载荷拒绝。数据库副作用和 Outbox 记录必须在同一事务中提交。
- BR-06：Runner 只能领取与其能力、工作空间、有效会话和当前租约匹配的 delivery；所有领取、续租和回执携带 fencing token。旧 token 的写入必须拒绝。
- BR-07：Runner 不直连业务数据库、不持有用户 JWT，不接收任意脚本、Shell、绝对文件路径或任意 URL。
- BR-08：Electron renderer 保持 `sandbox=true`、`contextIsolation=true`、`nodeIntegration=false`；默认拒绝 Web 权限、新窗口和非受信导航，只通过窄 preload IPC 暴露明确能力。
- BR-09：打包运行必须显式配置冻结的 HTTPS API Origin。仅在应用未打包的显式开发 / 测试态，才允许 `http://127.0.0.1`、`http://localhost` 或 `http://[::1]`；所有环境都拒绝 credentials、query、fragment、非精确 loopback 和证书错误降级。当前固定 REST / SSE 使用 `redirect: 'manual'` 并拒绝所有 3xx，避免认证或 Authorization 在 final URL 检查前被重放；失败时只显示脱敏原因。
- BR-10：当前切片的网络目标、fixture 和 UI 文案均不得包含真实账号、真实客户、真实商品或可执行外部动作；任何新增真实目标均使当前授权失效并重新按 L3 审查。
- BR-11：SSE 只加速展示。首次进入、任务页刷新或应用重启必须先取得同一一致性视图下的 Workspace bootstrap（当前 Task 页、Runner、Capability 与 workspace-wide 游标），再续订事件；单个 Task 的 ETag / 快照不能代替 Workspace 流起点，客户端本地状态不成为真相。
- BR-12：结果未知与失败分开；未获得权威回执的动作不得自动重试为“成功”，也不得自动创建第二次副作用。
- BR-13：本 Feature 的 Agent Runtime 只实现本地离线骨架、Fake transport / FakeModelPort 和契约测试。Agent Worker credential / session / job 数据表、服务端 AgentJob round-trip、真实 Provider adapter 启用和真实模型流量均不在本次范围。
- BR-14：Workspace 角色固定为 OWNER / OPERATOR / VIEWER，并与 `aden:*` 功能权限、membership 同时校验。三者均可读取获授权空间的当前投影；OWNER / OPERATOR 可在具备对应功能权限时创建和命令 Task，其中 `SUBMIT_FOR_VALIDATION` 要求 `aden:task:command`、`REQUEST_CANCEL` 要求 `aden:task:cancel`，二者不互相隐式授权；只有 OWNER 可 enroll / revoke Runner，VIEWER 不可写。平台 `workspace:create` 独立授权并建立首个 OWNER；正式成员管理、角色变更和 Workspace 删除不在本 Feature。
- BR-15：现有 RuoYi 全局 CORS 配置不作为 Aden 安全边界。当前 `/api/v1/aden/**` 没有浏览器调用方，服务端必须在共享 `CorsFilter` 之前拒绝全部带 `Origin` 的请求和 preflight，返回真实 403 ErrorEnvelope；无 Origin 的 Electron main / Runner / Agent HTTP 客户端不受影响。未来浏览器接入必须另行批准精确 allowlist，不能继承通配 Origin。

## 6. 进入真实连接器前的重新分流

任何以下动作不属于本 Feature 当前授权：登录个人微信或电商账号、读取真实聊天 / 商品 / 订单、调用真实 ERP 或模型、安装高权限 Runner、控制用户桌面、发送消息、创建采购动作、上传真实证据、部署公网服务。进入其中任一项前，必须以目标环境、账号、数据、动作、数量、费用、留存、停止条件和恢复方式形成独立 L3 执行包，并完成适用的权限 / 隐私 / 安全独立复核。

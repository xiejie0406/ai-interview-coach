## 使用方式

- 第一步：打开窗口 00，保持它只做协调。
- 第二步：同时打开 01–04，把对应文件中的整段提示词粘贴进去。
- 第三步：完成后把四个窗口交接给 00；用户决定 Gate A/Gate C 并由单一 owner 回写 Canonical 文件。
- 第四步：满足激活门后运行 05，用户批准任务包。
- 第五步：先单独运行 10；它交接共享骨架后，再同时运行 11–14。
- 第六步：11–14 完成后运行 15。构建/测试仍只能在批准范围执行。

## 当前候选实现续作：Wave 3

Foundation、Domain/Application 第一波和前端第二波已经形成局部候选源码，但运行证据仍为 `NotRun`。继续编码时使用：

1. [Wave 3 索引](第3波代码落地多窗口提示词索引.md)。
2. 先打开窗口 20，由它只读协调目录 owner、启动门和交接。
3. 先并行窗口 21–23；窗口 21 的首轮产物必须再经过窗口 27 契约收口。
4. 窗口 23 交接后运行窗口 31，先收口跨域边界、幂等四态与匿名注册 scope。
5. 窗口 31 交接后运行窗口 27；窗口 23、27、31 交接后串行运行窗口 28。
6. 窗口 22、27、28、31 交接后运行窗口 30，回填 Core 与业务 Persistence/SQL 到最新权威模型的映射。
7. 窗口 30 交接后先运行窗口 32，建立真实 durable `stream_event`、cursor 和 Last-Event-ID replay；不能让 REST 用 Outbox ID 或内存 sequence 代替。
8. 窗口 22、23、27、28、30、31、32 交接后再并行窗口 24–25。
9. 窗口 24 交接后运行窗口 29，收口 Session Security 与 Boot Bean 装配。
10. 最后运行窗口 26，只做静态集成审查；构建、测试、服务和 Git 仍需独立授权。

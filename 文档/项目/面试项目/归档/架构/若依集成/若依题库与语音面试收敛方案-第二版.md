## 1. 新结论

最终只保留一套“若依 AI 面试”产品，不再维护旧项目、移动端或多套上游副本：

```text
若依 AI 面试产品仓
├── apps/platform-backend   # 唯一 Java 后端、唯一 RuoYiApplication
├── apps/admin-web          # 若依管理端
├── apps/portal-web         # 用户端 Web（PC + H5）
├── contracts               # 只保留题库、面试、语音所需契约
└── docs                    # 只保留当前架构、运维、验证和历史索引
```

本轮产品范围只包含：

1. **面试题库**：后台维护并发布，用户浏览、搜索、查看答案和保存个人答案。
2. **语音面试**：Web 端录音、ASR、转写修正、回答提交、TTS、断线恢复和文字降级。
3. 语音面试所依赖的最小文本面试会话：创建会话、当前题、提交回答、下一题、结束。

明确不做：移动 App、支付、学习计划、报告扩展、运营中心、用户创建公共题目和旧身份兼容。它们不得阻塞本轮交付，也不得继续留在运行入口。

## 2. 为什么这样重排

当前仓库的问题不是缺少代码，而是代码和事实源太多：旧 React、旧 Spring Boot、三套 RuoYi 上游副本、三端客户端以及大量历史源码同时存在。继续全量迁移会把“两个功能做完善”扩大成整个平台重写。

V2 采用四个收敛原则：

- **先减范围**：只做题库与 Web 语音面试。
- **先题库、后语音**：题库能先验证 RuoYi 登录、RBAC、业务库、后台发布和门户读取。
- **只留一个身份和后端进程**：RuoYi JWT/RBAC 与 `ruoyi-admin` 是唯一入口。
- **最后一次性删旧栈**：旧代码先冻结为只读迁移源，两个功能验收后统一删除，避免边搬边丢参考。

| 目录 | 最终职责 |

| 根 `pom.xml` | 只聚合旧 `backend`，删除后失效 |

## 4. 目标技术架构

### 4.1 运行时

```text
admin-web ─┐
           ├── RuoYi JWT/RBAC ──> ruoyi-admin + ruoyi-interview
portal-web ┘                         ├── MySQL：sys_user/sys_role/sys_menu
                                    ├── PostgreSQL：题库/会话/语音业务事实
                                    ├── Redis：RuoYi Token、一次性 WS ticket、短期恢复状态
                                    ├── S3/MinIO：音频对象
                                    └── ASR/TTS Provider：受控适配器
```

- 不新增第二个 `main`、`SecurityFilterChain`、账号表、Session Cookie 或 CSRF 体系。
- MySQL 只负责 RuoYi 系统事实；PostgreSQL 继续承载已有加密、版本、题库和语音模型。
- 本地开发可使用本地对象存储和 fake ASR/TTS；生产必须使用 S3/MinIO 与显式 Provider 配置。fake 只能证明协议与失败恢复，不能替代真实 Provider UAT。

### 4.2 权限

| 角色 | 主要权限 |
|---|---|
| 匿名用户 | 读取已发布题库列表和详情 |
| 登录用户 | 保存个人答案、创建/恢复面试、提交文本/语音回答、删除自己的音频 |
| 题库编辑 | 创建草稿和新版本、维护标准答案/Rubric、提交审核 |
| 题库审核 | 审核、驳回、发布、下线 |
| 系统管理员 | RuoYi 用户/角色/菜单、Provider 状态和审计查询 |

公开 GET 不放在类级登录权限下；所有写操作从 RuoYi principal 取用户和权限，不能信任前端传入的用户、角色或 tenant。

## 5. 功能规格收缩

### 5.1 面试题库 P0

保留：

- 12 个固定模块、约 600 道题的版本化导入。
- 标题关键词、模块、难度和游标分页筛选。
- 题目详情、标准答案和稳定版本元数据。
- 登录用户保存个人答案；个人答案不覆盖公共答案。
- Admin 草稿、新版本、Rubric、提交审核、驳回、发布和下线。
- 幂等键、`If-Match`、权限拒绝、来源/版权记录和审计事件。

删除/延期：

- 普通用户新增公共题目。
- AI 自动批量生成题目。
- 收藏、练习计划、评分报告和社区功能。

### 5.2 语音面试 P0

保留：

- 登录后创建或恢复最小面试会话。
- consent、麦克风授权、设备/codec/额度/Provider preflight。
- `client.hello/start/chunk/stop/cancel`、sequence、ACK/NACK、背压和大小/时长限制。
- ASR 最终转写、低置信提示、用户修正和显式确认。
- 转写确认与回答提交幂等、原子；成功后进入下一题。
- TTS 播放/取消/失败终态；任何语音失败可无损切换文字输入。
- Redis 一次性 ticket、SSE/WS 断线恢复和过期处理。
- 音频保留期、用户删除、对象存储删除结果和审计。

删除/延期：

- Native App 录音。
- 多人实时面试、实时波形分析、声纹、情绪识别。
- 多 Provider 自动路由；P0 只选一个 ASR/TTS Provider，另保留 fake adapter。

## 6. 新执行顺序

### Wave 0：冻结旧栈和锁定基线

- 旧 `frontend/`、`backend/` 只读；不再修 Bug、不再新增功能。
- 登记当前用户修改和未跟踪文件，避免迁移覆盖。
- 固定题库模块、Provider、对象存储、Redis、业务库配置和契约版本。
- 生成删除候选的文件数、哈希、入链和恢复清单。

完成门：旧栈无新写入；V2 Feature Spec、设计和任务包获批准。

### Wave 1：先完成题库

1. 修正公开 GET 与 RuoYi 权限边界，保留写接口权限。
2. 补齐题库 Admin application contract 和 Controller，移除 `CAPABILITY_UNAVAILABLE` 占位。
3. 完成 600 题导入器、重复/来源/结构校验和幂等发布。
4. 完成 Admin 管理页与 Portal 三栏题库。
5. 完成权限、跨租户、版本冲突、公开读取和个人答案验证。

完成门：题库 P0 AC 全部有 EV，用户完成关键 UAT。

### Wave 2：完成最小文本面试骨架

1. 会话创建、当前题、回答提交、下一题、结束与恢复。
2. 题目引用锁定到题库已发布版本。
3. Portal 面试房间只保留一个文本回答事实源。

完成门：纯文本流程可完整完成一次面试，语音失败时有可靠落点。

### Wave 3：完成语音闭环

1. PostgreSQL/Flyway/`JdbcVoiceRepository` 可从空库迁移并回读。
2. Redis ticket 替换生产用内存 ticket；验证单次消费、过期和主体绑定。
3. 对象存储、ASR 和 TTS adapter 装配；先 fake 协议测试，再真实 Provider UAT。
4. 转写修正/确认与回答提交实现事务和幂等。
5. WS/SSE 恢复、背压、取消、失败降级和音频删除闭环。
6. Portal PC/H5 完成交互；Admin 只做状态、失败原因和审计查看。

完成门：语音成功路径、Provider 失败、拒麦、断网、刷新、越权和删除均有证据。

### Wave 4：切换与验收

- 只启动 `apps/platform-backend/ruoyi-admin`。
- Admin 与 Portal 使用同一 RuoYi 登录态和权限。
- 完成题库、文本面试、语音面试三个端到端 UAT。
- 扫描旧 API、Cookie、端口、进程、依赖和文档链接，确认旧栈 0 运行依赖。

完成门：用户/业务 owner 明确验收；上线就绪仍需独立结论。

### Wave 5：一次性删除旧项目

- 在仓库外创建可回读压缩备份，并创建 Git bundle；二者都要记录校验值。
- 按第 3.2 节精确清单删除旧目录和散落文件。
- 将需要保留的历史结论压缩成 `文档/参考/旧迁移索引.md`，不保留旧运行说明。
- 复核只剩三个运行工程、当前契约和当前文档。

完成门：删除前后清单一致、备份可回读、无断链；Git 提交/推送/发布仍需分别授权。

## 8. 执行包与授权边界

用户批准本 V2 后，可继续形成逐文件 TASK 包；源码修改、测试代码、运行命令、外部 Provider、数据迁移、浏览器 UAT、删除、Git 和发布仍按各自执行包授权。

建议首个实施包只覆盖 **Wave 1 题库**，允许修改：

- `apps/platform-backend/ruoyi-interview` 的 catalog application/controller/persistence/configuration/test。
- `apps/admin-web` 的题库 API、页面和路由。
- `apps/portal-web` 的题库页面/API；不得覆盖当前身份/面试房间的用户修改。
- 题库 Feature Spec、设计、任务、验证和验收文档。

首个实施包不启动服务、不连接真实数据库、不调用外部 Provider、不删除旧目录、不执行 Git；这些动作在明确命令、环境、影响和停止条件后另行确认。

## 9. 当前待用户确认

推荐默认决定：

- 采用 Web 优先 V2，取消本轮移动端。
- 最终只保留 `platform-backend + admin-web + portal-web` 三个运行工程。
- 普通用户不能创建公共题目，只能保存个人答案。
- 语音 P0 只接一个 ASR/TTS Provider，必须有文字降级。
- 先完成题库，再完成文本面试骨架和语音，全部验收后再删除旧项目。

用户确认后，下一步进入 Wave 1 的 Feature Spec 修订和逐文件任务拆分；当前未执行构建、测试、启动、外部调用、删除或 Git 操作。

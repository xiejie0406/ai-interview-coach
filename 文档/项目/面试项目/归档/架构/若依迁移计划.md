## 3. 移植原则（硬约束）

### 3.1 逻辑层可复用，视图层不复用

- React 组件（含 Tailwind / shadcn / react-router-dom 依赖）**全部重写**为 Vue 3 + Element Plus；
- 只复用"业务逻辑抽象"（API 调用路径 / 类型模型 / 状态机）。

### 3.2 API 路径对齐

- React 现有调用 `/api/v1/identity/*`、`/api/v1/catalog/*` 等路径**保持**；
- admin-web / portal-web 复用同一套 backend 路径，仅客户端实例变化。

### 3.3 类型模型迁移

- `frontend/src/shared/api/types.ts` 等共享类型**逐字段**翻译成 TypeScript 5.7；
- **不**引入 `frontend/` 的 `tsconfig.json` / `package.json`。

### 3.4 hooks 抽象翻译

- `frontend/src/features/*/hooks/*.ts` 翻译成 `apps/<端>/src/composables/*.ts`（Pinia composition）；
- 命名约定：React `useFoo` → Vue `useFoo`（保持调用习惯）。

### 3.5 store 翻译

- `frontend/src/features/voice/store/` 翻译成 `apps/<端>/src/stores/voice.ts`（Pinia）；
- `frontend/src/shared/session/` 翻译成 `apps/<端>/src/stores/session.ts`。

### 3.6 不引入

- React / Tailwind / shadcn / react-router-dom 任何依赖；
- 原 `frontend/package.json` 的所有依赖。

## 6. 切换期双兼容契约

admin-web / portal-web 在 R2 期间**同时支持**：

| 调用方 | 路径 | 鉴权 |
|---|---|---|
| 旧 React `frontend/` | `/api/v1/*`（保持现有路径） | DEC-028 Cookie Session |
| 新 Vue 3 admin-web / portal-web | `/api/v1/*`（路径不变，仅客户端实例变化） | DEC-028 Cookie Session |

bridge module（`规格-后端统一网关层.md`）必须**双兼容**——同一组端点既能服务旧 React 也能服务新 Vue 3。

切换流程：

```
R2 上线 admin-web（双兼容）
  ↓
灰度：Vue 3 客户端对 X% 用户开启
  ↓
旧 React 客户端流量监控 = 0%
  ↓
下线旧 React 端点（仅删除旧客户端实例，不删除 server 端点）
  ↓
R4 上线 portal-web（同样灰度流程）
  ↓
R5 上线 mobile（独立灰度）
```

> **强约束**：旧 React 端点的 server 端**至少保留 6 个月**——旧客户端可能在用户本地缓存中运行。server 端删除走 R7 决策。

## 0. 目的、范围和事实边界

本文件是供用户直接审阅和批准的唯一产品审查入口：正文给出“截断后 Canonical 产品规格重建候选”，附录 A 保留调研来源、用户旅程、全量功能审计、范围包和候选决策点。它不修改 `docs/product/产品需求文档.md`、`docs/architecture/技术架构.md`、`docs/decisions/决策登记表.md`、`docs/phases/phase-*.md` 或任何源码。

现有 PRD 在 `FUNC-VOICE-002` 行出现字面截断标记；现有技术架构的数据模型段也存在截断。原文不可从当前文件可靠恢复，本文件不声称找回原文，也不把候选 ID 写入 Canonical。下文的 `CAND-*` 只表示待批准的重建候选；只有用户批准并由唯一 owner 回写后，才可转成正式 `REQ-*`、`BR-*`、`AC-*` 或 `FUNC-*`。

本轮处理目标：

1. 在明确假设的前提下，补齐语音、报告、学习、商业和后台功能的可审查候选。
2. 把候选与现有 `REQ-01..15`、`BR-01..12`、`AC-01..14` 的影响写清楚。
3. 给出 Gate A、Gate C 可直接复制的决定文本，但不代替用户把 `Pending` 改为 `Accepted/Deferred`。
4. 给出 Canonical PRD 未来逐段回写清单，避免在代码或 Phase 文档中偷偷补写需求。

本文件不批准具体供应商、价格、Java/Spring/React 版本、支付渠道、数据区域、保留 SLA、数据库表名或生产部署方案；这些属于 `DEC-033..058` 的 Gate B 决策，必须在对应实现包前通过验证任务关闭。

## 1. “推荐包 A”的定义与采用假设

现有资料中同时存在“Gate A 推荐决策包”和“范围包 A/B/C”两个字母体系。为避免把两个 A 混为一谈，本文件明确采用以下术语：

> **推荐包 A（本文件定义）= 接受 Gate A 推荐项的产品决策包 + 接受 Gate C 延后建议；业务范围采用“推荐商业 MVP”的能力集合，但暂不接入真实支付。**

这不是附录 A 中“范围包 A（精简 MVP）”的同义词。若用户要选择范围包 A（精简 MVP），只需在批准文本中改填 `SCOPE=简版 MVP`，语音和权益候选会按本文件第 8 节降级；在用户明确选择前，本候选保持“推荐商业 MVP、无真实支付”的基线。

## 1. 调研结论摘要

### 1.1 结论

推荐收敛为“**先证明技术面试反馈闭环，再逐步证明语音和付费价值**”的个人用户产品：

1. P0 不应等于 PRD 中所有 P0 行。首发应把公开获客、账号/档案、受控题库、文本短面试、可解释报告、弱项复练、隐私删除和最小内容治理连成一条闭环。
2. 级联语音（ASR → 文本面试 Agent → TTS）建议作为“推荐商业 MVP”的受控 P0，而非“精简 MVP”的必选项；其前提是国内可用供应商、数据地域、删除 SLA、成本上限和失败降级决策已经关闭。
3. 对技术答案的价值不来自“像真人聊天”，而来自版本化题目/Rubric、可定位证据、证据不足提示、用户纠错和 Golden Set 校准。没有这些，不能把结果宣传为权威评分。
4. 当前最显著的规格风险不是功能数不够，而是 PRD 在语音段后截断、REQ/AC 粒度不足、支付/退款/隐私生命周期和后台发布审核没有完整可审查行为。
5. JD/简历、真实支付、完整订阅运营、Realtime 语音、B2B 和视频能力不应进入首个价值验证切片。

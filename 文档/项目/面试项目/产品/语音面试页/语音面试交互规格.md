# AI Interview Coach — 语音面试交互规格说明 v1.0

> 本文用于配合 `语音面试三栏原型-v2.html` 原型进行前端 / 后端 / AI Agent 开发。
>
> **重要：原型只表达视觉结构，本文才是交互与业务行为的最终约束。**
>
> 开发 AI 不得仅根据页面视觉自行推断交互逻辑，应优先遵守本文中的状态机、事件、自动行为和验收标准。

---

# 1. 产品核心定义

本产品不是“文字聊天面试”，也不是“固定题库语音播放”。

它是一个：

**以语音为主、实时转写为辅、AI 动态出题和追问的实时面试系统。**

核心循环：

```text
用户配置面试范围 / 大纲
        ↓
AI 根据上下文动态生成问题
        ↓
AI 自动语音朗读问题
        ↓
AI 朗读结束
        ↓
系统自动打开麦克风
        ↓
用户语音回答
        ↓
实时 ASR 转写
        ↓
系统判断用户回答结束
        ↓
关闭麦克风
        ↓
AI 分析回答
        ↓
AI 决策：追问 / 换知识点 / 提升难度 / 降低难度 / 结束
        ↓
AI 生成下一题并自动朗读
        ↓
循环
```

---

# 2. 产品交互原则

## 2.1 语音优先

用户的主要输入方式必须是：

**说话。**

文字转写只是辅助信息，不是主要输入框。

默认情况下：

- 不显示文字输入框。
- 用户不需要点击“发送”。
- 用户说完后，系统自动判断回答结束。
- AI 生成问题后自动朗读。
- AI 朗读结束后自动开始收音。

---

## 2.2 AI 问题必须自动朗读

AI 每生成一个新问题后：

```text
1. 先把问题内容加入对话记录。
2. 立即调用 TTS。
3. 页面进入 AI_SPEAKING 状态。
4. 播放 AI 语音。
5. 播放过程中禁止自动开启用户麦克风。
6. 播放结束后自动进入 USER_LISTENING。
7. 自动开始用户语音识别。
```

禁止出现：

```text
AI 已生成问题
↓
用户还需要手动点击“播放”
↓
才听到问题
```

正确行为是：

**AI 问题生成后自动播放。**

“重新播放”按钮只是辅助操作。

---

# 3. 三栏页面职责

## 3.1 左栏：面试大纲

左栏不是题目列表。

它只表示：

```text
考察范围
能力模块
当前进行到哪个模块
模块完成情况
```

例如：

```text
01 项目经历
02 Java 基础
03 集合与并发
04 JVM
05 Spring / MySQL
06 系统设计
```

这些不是固定问题。

AI 可以：

- 一个模块问 1 个问题。
- 一个模块连续追问 3~5 次。
- 根据用户表现提前结束某个模块。
- 根据用户表现调整后续模块难度。

### 禁止

不要提前生成：

```text
第1题
第2题
第3题
...
第20题
```

然后机械播放。

---

# 4. 中间栏：核心语音对话区

中间区域是整个产品最重要的区域。

它同时承担：

```text
AI 语音提问
用户语音回答
实时转写
历史对话
当前语音状态
```

视觉层级必须满足：

```text
当前正在发生的语音交互
        >
最近一轮问答
        >
历史问答
```

---

# 5. 对话消息模型

每一轮对话推荐统一保存为：

```json
{
  "id": "turn_xxx",
  "role": "assistant | user",
  "type": "question | follow_up | answer",
  "text": "转写文本",
  "audioUrl": "...",
  "duration": 12.4,
  "createdAt": "...",
  "outlineNodeId": "concurrency",
  "status": "generating | speaking | listening | completed"
}
```

# 6. AI 消息交互

## 6.1 AI 正在生成问题

状态：

```text
AI_THINKING
```

页面表现：

```text
AI 正在根据你的回答生成下一次追问…
```

此时：

- 麦克风关闭。
- 用户不能说话。
- 不显示空白 AI 气泡。
- 不提前显示尚未生成完成的问题。

---

## 6.2 AI 问题生成完成

一旦 LLM 返回完整问题：

```text
插入 AI 消息
↓
开始 TTS
↓
进入 AI_SPEAKING
```

页面：

```text
AI 面试官
[问题文字]

🔊 正在朗读  00:05 / 00:12
```

问题文字可以同步显示。

**但是文字不是让用户自己阅读后再操作。**

语音必须自动播放。

---

## 6.3 AI 朗读过程中

状态：

```text
AI_SPEAKING
```

必须：

- 显示明显的 AI 正在说话状态。
- 麦克风默认关闭。
- 禁止 ASR 把 AI 自己的声音识别成用户声音。
- 显示语音波形或播放动画。
- 支持“跳过朗读”。

可提供：

```text
重新播放
暂停 / 继续
跳过朗读
```

---

## 6.4 AI 朗读结束

TTS 播放结束事件：

```text
onended
```

触发：

```text
AI_SPEAKING
    ↓
USER_LISTENING
```

自动执行：

```text
打开麦克风
启动 VAD
启动 ASR
显示“请回答”
```

不要求用户再点一次麦克风。

---

# 7. 用户回答交互

## 7.1 自动开始收音

进入：

```text
USER_LISTENING
```

之后：

```text
麦克风自动开启
ASR 自动开始
VAD 自动开始
```

页面：

```text
● 正在聆听

直接回答即可
```

---

## 7.2 实时转写

实时 ASR 结果分两种：

```text
interim result
final result
```

例如：

```text
interim:
我认为hashmap主要

final:
我认为 HashMap 主要由数组、链表和红黑树组成。
```

UI 不应该每收到一个 token 就新增一条聊天消息。

正确方式：

```text
当前实时转写区域
不断更新当前句子
```

最终确定后，再加入本轮回答。

---

# 8. 实时转写 UI 规则

实时转写必须明显区别于历史消息。

建议：

```text
┌─────────────────────────────┐
│ ● 正在实时转写              │
│                             │
│ 我认为 HashMap 在 JDK8 中…  │
│                           ▌ │
└─────────────────────────────┘
```

这里的文字：

- 是实时变化的。
- 尚未完成时不要作为正式消息保存。
- 用户停顿后可以自动断句。
- 用户继续讲话时继续追加。

---

# 9. 如何判断“用户回答结束”

不能简单使用：

```text
3 秒没有声音 = 回答结束
```

否则用户思考时会被误判。

推荐组合判断：

```text
VAD 静音时间
+
回答持续时间
+
ASR 文本完整度
+
语义完整度判断
```

例如：

### 情况 A

用户停顿 1.5 秒。

```text
不要结束。
```

### 情况 B

用户停顿 3 秒，但刚刚说：

```text
“这个问题我觉得主要有三个方面，第一个……”
```

明显没说完。

```text
不要结束。
```

### 情况 C

用户说：

```text
“所以我最终会选择逻辑过期加异步重建，基本就是这样。”
```

并静音 2 秒。

可以判断：

```text
回答完成。
```

---

# 10. 用户手动结束回答

虽然系统应自动判断，但仍必须保留：

```text
✓ 回答完成
```

按钮。

用户点击后：

```text
立即停止收音
↓
结束当前 ASR
↓
固定当前转写
↓
进入 AI_THINKING
```

---

# 11. 用户暂停

用户可以点击麦克风：

```text
正在聆听
↓
暂停
```

暂停时：

- 不提交回答。
- 不触发 AI 出下一题。
- 保留已有转写。
- 再次点击继续当前回答。

---

# 12. 用户打断 AI

建议第二阶段支持。

当 AI 正在朗读时用户开始讲话：

```text
BARGE_IN
```

系统：

```text
停止 TTS
↓
开启 ASR
↓
进入 USER_LISTENING
```

这是类似豆包 / ChatGPT Voice 的体验。

第一版如果实现成本高，可以暂时关闭。

---

# 13. AI 如何决定下一步

AI 不是简单执行：

```text
currentQuestionIndex++
```

而应该执行：

```text
AnalyzeAnswer
↓
UpdateInterviewState
↓
DecideNextAction
```

建议 AI 返回结构化结果：

```json
{
  "answerEvaluation": {
    "correctness": 0.82,
    "completeness": 0.68,
    "depth": 0.72,
    "communication": 0.80
  },
  "coveredPoints": [
    "mutex lock",
    "logical expiration"
  ],
  "missingPoints": [
    "lock renewal",
    "fallback strategy"
  ],
  "nextAction": "FOLLOW_UP",
  "nextTopic": "cache_breakdown",
  "difficulty": 3,
  "reason": "用户理解主要方案，但没有解释锁超时问题"
}
```

---

# 14. nextAction 定义

推荐至少支持：

```text
FOLLOW_UP
继续追问当前问题

NEXT_TOPIC
进入下一个大纲模块

DEEPEN
提高难度继续追问

SIMPLIFY
降低难度

SCENARIO
转换成业务场景题

CLARIFY
用户表达不清楚，要求补充

END
结束面试
```

---

# 15. AI 动态出题规则

例如用户刚才说：

```text
我项目里用了 Redis 做缓存。
```

AI 可以动态追问：

```text
你们为什么使用 Redis？
```

用户回答后：

```text
那如果热点 Key 失效呢？
```

继续：

```text
互斥锁导致请求阻塞怎么办？
```

继续：

```text
如果锁持有者挂了呢？
```

这才是动态面试。

禁止：

```text
题库第 17 题：什么是缓存击穿？
```

---

# 16. 当前状态机

必须使用明确状态，不要靠多个 boolean 拼凑。

推荐：

```text
PREPARING
    ↓
AI_THINKING
    ↓
AI_SPEAKING
    ↓
USER_LISTENING
    ↓
USER_PAUSED
    ↓
USER_FINISHING
    ↓
AI_THINKING
```

结束：

```text
INTERVIEW_FINISHED
```

异常：

```text
ERROR
RECONNECTING
```

---

# 17. 状态转换

```text
PREPARING
   │
   ▼
AI_THINKING
   │ LLM返回问题
   ▼
AI_SPEAKING
   │ TTS播放结束
   ▼
USER_LISTENING
   │
   ├── 用户暂停 ──► USER_PAUSED
   │                 │
   │                 └──继续 ──► USER_LISTENING
   │
   └── 回答结束
             │
             ▼
      USER_FINISHING
             │
             ▼
       AI_THINKING
```

---

# 18. 右侧 AI 状态栏

右栏不能变成“答案提示器”。

主要展示：

```text
当前考察模块
当前考察能力
AI 已识别知识点
对话状态
面试进度
```

例如：

```text
当前考察：
缓存击穿

已覆盖：
✓ 互斥锁
✓ 逻辑过期

正在判断：
缓存一致性
```

### 不建议实时展示

```text
正确答案
标准答案
完整知识点
明显的实时分数
```

否则相当于给用户作弊提示。

---

# 19. 自动滚动规则

新消息出现时：

```text
默认自动滚动到底部。
```

但是如果用户手动向上查看历史：

```text
不要强制把用户拉到底部。
```

此时显示：

```text
↓ 回到最新
```

进入面试页面：

```text
连接 WebSocket
↓
检查麦克风权限
↓
初始化 ASR
↓
初始化 TTS
↓
加载 interviewSession

AI 生成开场问题

自动朗读
```

# 21. 麦克风权限

首次进入：

```text
请求麦克风权限
```

如果拒绝：

不能直接进入正常页面。

应该展示：

```text
无法开始语音面试

需要麦克风权限才能进行 AI 语音面试。

[重新授权]
```

---

# 22. 网络异常

如果 WebSocket 断开：

```text
RECONNECTING
```

UI：

```text
正在重新连接…
```

此时：

- 不丢失当前转写。
- 不重复发送已经提交的回答。
- 恢复后继续当前 session。

---

# 23. TTS 异常

如果 AI 文本生成成功，但 TTS 失败：

显示：

```text
语音播放失败
```

允许：

```text
重新播放
```

同时保留问题文字。

但不要直接跳到下一题。

---

# 24. ASR 异常

如果识别服务失败：

```text
语音识别暂时中断
```

允许：

```text
重新连接
重新录音
```

不要把空文本提交给 AI。

---

# 25. 防重复提交

每一个用户回答必须有唯一 ID：

```text
answerId
```

后端需要幂等。

避免：

```text
WebSocket 重连
↓
同一个回答提交两次
↓
AI 连续生成两个问题
```

# 28. AI 开发最容易做错的地方

开发时必须重点检查：

### 错误 1

AI 问题只显示文字，不自动朗读。

正确：

```text
新问题生成 → 自动 TTS。
```

### 错误 2

用户需要点击麦克风才能开始答题。

正确：

```text
AI 朗读结束 → 自动开启麦克风。
```

### 错误 3

每一句 ASR 都创建聊天气泡。

正确：

```text
interim 在实时转写区域更新。
final 才进入历史记录。
```

### 错误 4

AI 从预生成题库依次读题。

正确：

```text
每一轮基于：
大纲 + 历史问答 + 用户表现
动态决定下一题。
```

### 错误 5

用户停顿 2~3 秒立即提交。

正确：

需要 VAD + 语义完整度共同判断。

### 错误 6

AI 说话的时候麦克风还在识别。

正确：

第一版：

```text
AI_SPEAKING → Mic OFF
```

除非明确实现打断模式。

### 错误 7

实时评分暴露正确答案。

正确：

面试过程中只显示非常弱的状态信息，完整评分结束后再展示。

# 29. 前端验收标准

完成页面后逐条测试：

- [ ] AI 第一题会自动生成。
- [ ] AI 第一题会自动朗读。
- [ ] 不需要用户点击播放。
- [ ] AI 朗读期间麦克风不会录入 AI 声音。
- [ ] AI 朗读结束自动开始收音。
- [ ] 用户说话时实时转写不断更新。
- [ ] interim 文本不会生成多条聊天消息。
- [ ] 用户暂停后不会提交回答。
- [ ] 用户继续后转写可以继续。
- [ ] 用户点击“回答完成”后停止收音。
- [ ] 自动判断回答结束后也能停止收音。
- [ ] 回答提交后 AI 自动分析。
- [ ] AI 根据回答生成追问，而不是固定下一题。
- [ ] 新问题生成后自动播放。
- [ ] 历史语音可以重新播放。
- [ ] 左侧大纲不会展示固定题目。
- [ ] 右侧不会泄露标准答案。
- [ ] WebSocket 重连不会重复提交回答。
- [ ] 麦克风拒绝授权时有独立错误状态。
- [ ] ASR/TTS 错误均可以恢复。
- [ ] 面试结束后生成完整面试报告。

# 30. 推荐给 Coding Agent 的任务提示词

下面这段可以直接给 Claude Code / Codex / Cursor：

```text
请严格按照以下两份材料实现 AI 语音面试页面：

1. 语音面试三栏原型-v2.html
   - 只作为视觉 UI 参考。

2. 语音面试交互规格.md
   - 作为业务逻辑和交互行为的唯一事实来源。
   - 当视觉原型和交互文档冲突时，以交互文档为准。

这个页面不是文字聊天产品，而是 Voice First 的 AI 面试系统。

必须实现完整状态机：

PREPARING
→ AI_THINKING
→ AI_SPEAKING
→ USER_LISTENING
→ USER_FINISHING
→ AI_THINKING

核心要求：

1. AI 问题由 LLM 动态生成，不允许使用固定题目数组模拟业务。
2. AI 问题生成完成以后必须自动调用 TTS 并自动播放。
3. AI 播放过程中默认关闭用户麦克风。
4. AI 播放结束以后自动启动麦克风、VAD、ASR。
5. 用户说话过程中显示 ASR interim 实时转写。
6. ASR interim 只更新当前实时转写区域，不创建聊天记录。
7. ASR final 才进入正式历史对话。
8. 用户回答结束以后自动调用 AI 分析回答。
9. AI 根据回答动态决定 FOLLOW_UP / NEXT_TOPIC / DEEPEN / SIMPLIFY / SCENARIO / CLARIFY / END。
10. 下一题生成完成以后再次自动 TTS，从而形成连续语音面试循环。

不要自行简化以上交互。

在编码前，请先输出：
- 状态机设计
- 组件拆分
- WebSocket 事件
- ASR/TTS 生命周期
- 异常处理方案

确认设计与 interaction spec 一致以后再开始修改代码。

代码完成后，请根据文档第 29 节的验收清单逐条自测，并输出每项 PASS / FAIL。
```

# 31. 推荐工程文件组织

不要只保存一个 HTML 原型。

建议项目至少存在：

```text
文档/项目/面试项目/产品/语音面试页/
├── 语音面试产品说明.md
├── 语音面试交互规格.md

├── 语音面试接口说明.md
└── 语音面试三栏原型-v2.html
```

其中：

```text
product.md
负责说明“做什么”

interaction-spec.md
负责说明“用户怎么操作、系统怎么响应”

state-machine.md
负责说明“当前系统是什么状态”

api.md
负责说明“前后端怎么通信”

prototype.html
只负责说明“长什么样”
```

# 32. 最重要的一条开发约束

以后不要给 AI：

```text
“照着这个原型开发。”
```

应该给：

```text
“原型负责 UI，
交互规格负责行为，
状态机负责流程，
API 文档负责数据，
验收清单负责判断是否完成。”
```

这样 Coding Agent 出错率会明显下降。

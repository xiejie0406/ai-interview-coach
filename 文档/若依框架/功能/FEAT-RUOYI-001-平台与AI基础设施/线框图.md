## A. 系统管理 → 平台密钥

```text
┌──────────────────────────── 平台密钥 ────────────────────────────────────────────┐
│ [用途/名称________] [所属服务▼] [类别▼] [接入状态▼] [查询]     [新增平台密钥] │
├────────┬───────────────┬────────────┬───────────┬──────────┬──────────────────┤
│服务    │用途/别名      │类别        │接入状态   │最近轮换  │操作              │
├────────┼───────────────┼────────────┼───────────┼──────────┼──────────────────┤
│Fashion │Java↔Python认证│服务间认证  │待接入     │—         │详情 / 接入说明   │
│面试    │敏感数据加密   │业务加密    │环境配置中 │—         │详情 / 接入说明   │
│若依    │JWT 签名       │平台签名    │环境配置中 │—         │详情 / 接入说明   │
└────────┴───────────────┴────────────┴───────────┴──────────┴──────────────────┘
  详情抽屉：用途、消费服务、当前版本、状态、接入方式、轮换依赖、操作记录
  已接入项：录入/轮换、启用/停用（需权限和确认）
```

平台密钥允许登记固定用途，实际接入状态必须基于消费者完成替换和验证；在库中有一条记录不等于服务已使用它。不同进程共用的密钥需先完成双端分发，才能显示“已接入”。

发布后版本不可原地修改。新运行固定引用已发布角色版本及配置哈希；已有运行继续使用已固定版本。回退是把当前指针切回已有已验证版本，留审计记录，不覆盖版本正文。选择 AI 密钥时只选择用途别名；发布前校验该密钥与模型/供应商匹配，但发布不自动启用真实 Provider。空状态提示先建角色、再建草稿、最后发布；校验错误停留在对应字段。

## 权限与关键交互

若依“角色管理”仍只管理**操作员权限**：平台密钥查看/写入/启停/审计、AI 密钥查看/写入/启停/审计、AI 角色查看/编辑/发布各自独立。它不是上图的“AI 角色”。无权用户直访 API 也被拒绝。三个模块都不提供批量明文导出；危险动作须二次确认和填写原因；键盘可操作弹窗与表格动作。

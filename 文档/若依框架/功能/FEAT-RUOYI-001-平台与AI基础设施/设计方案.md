## 1. 用户决定和模块边界

用户明确要求三个模块：**平台密钥、AI 密钥、AI 角色**。AI 角色指助手的人设、提示词和模型配置，不是若依用户角色。密钥数据用 MySQL 管理。导航建议为“系统管理 → 平台密钥”和“AI 基础设施 → AI 密钥 / AI 角色”。后台操作员的授权仍由若依已有角色管理负责，但只作为三模块的权限入口。

| 模块 | 拥有的业务对象 | 明确不拥有 |
|---|---|---|
| 平台密钥 | 非 AI 的平台/服务间/业务加密凭据、用途、版本、轮换与接入状态 | AI Provider 凭据；AI 助手人设；若依用户角色 |
| AI 密钥 | 模型、语音、图像等 AI Provider 凭据组、用途、版本、供应商、启停 | 模型提示词；业务 Provider 开关；若依用户角色 |
| AI 角色 | AI 助手身份、目标、系统提示词、模型与参数、AI 密钥引用、版本发布 | 密钥明文；操作员权限；已发生业务运行的不可变快照 |

两个密钥模块使用共同的 MySQL 密文存储和轮换机制，但页面、权限、固定用途注册表与接口分类独立。AI 角色使用独立版本表；它通过 `ai_secret_ref` 引用 AI 密钥的用途标识，任何角色记录都不保存密钥值。

## 2. 活跃工程盘点与接入顺序

盘点只依据当前活跃代码、示例配置和项目控制页；未读取或输出本机真实密钥，不能从文件存在推断实际环境已启用。

| 现有值或能力 | 当前状态/消费者 | 归属与处理 |
|---|---|---|
| 面试 `INTERVIEW_DEEPSEEK_API_KEY` | Java DeepSeek adapter 启动时绑定 | **AI 密钥首批**；改为调用前按固定用途读取。模型名和 URL 仍为非秘密配置，后续与 AI 角色版本关联 |
| 面试火山语音 `API_KEY`，或 `APP_ID + ACCESS_TOKEN` | Java ASR/TTS adapter 启动时绑定 | **AI 密钥首批**；两种模式互斥，后一组原子保存和切换 |
| 智能选品真实图像/模型 Provider 密钥 | 图像 Provider adapter 当前 disabled；Python ProviderMode 固定 disabled | **AI 密钥预留固定用途**，没有当前真实值可迁移；真实 Provider 另需功能批准与联机验证 |
| Aden Agent 模型密钥 | 当前 Agent Runtime 使用 Fake/provider-disabled | **AI 密钥后续接入**；当前不创建伪造值或启用外呼 |
| 智能选品 Java↔Python `FASHION_SERVICE_*KEY_BASE64` / `FASHION_AI_AUTH_*KEY_BASE64` | 双进程 HMAC 服务认证 | **平台密钥**；先完成双端安全分发、active/previous 轮换和断线恢复，再切换来源 |
| 面试敏感信封密钥、选品客户联系人加密密钥、Aden Runner pepper | 数据加密或令牌派生 | **平台密钥后续接入**；须保留旧版本可解密能力和恢复演练，不能只复制新值到表里 |
| 若依 JWT secret、Redis 密码、APS/面试数据库口令及迁移账号 | 平台启动、缓存或数据库连接 | **平台密钥分阶段接入**；需先拆解启动顺序与连接生命周期。连接目标 MySQL 所需的最低数据库凭据是自举例外，无法仅存同一 MySQL 库内 |
| 生产排产 AI Provider 密钥 | 当前未发现实际 AI Provider 消费者 | 当前无可迁移值；出现真实消费者再登记固定用途 |
| 智能选品 `fq_agent` 与版本 | MySQL 已保存 Provider、模型、系统指令、配置、工具、护栏；后台有 Agent 版本页 | **AI 角色接入对象**；保留既有版本与运行引用，设计映射后分阶段收敛，不另造无关联的第二套生效角色 |
| 面试 Agent/Prompt 版本引用 | Java 有 `InterviewAgentConfigurationPort`、`PromptSchemaRegistryPort`，当前配置 registry；业务数据在 PostgreSQL | **AI 角色接入对象**；以稳定角色版本 ID 引用，面试侧保留业务快照，不跨库建立外键或事务 |
| Aden Agent 角色 | 当前 Fake 注册与版本边界，真实 Provider 未定 | 后续按 Aden 功能批准接入；不由统一角色页直接放开 Runner 权限 |

各消费者的代码来源统一切到 MySQL 模块；真实环境部署时仍须按业务依赖顺序录入和重启，不能通过保留运行时环境变量作为切换开关。只有目标环境完成迁移和定向验证，才可声称该环境已接入。AI 密钥和 AI 角色的首批对象以面试为主，智能选品既有 Agent 版本需做映射与兼容设计。

## 3. 功能需求和验收条件

### REQ / BR

- REQ-01：平台密钥独立管理非 AI 凭据，展示用途、消费服务、版本、状态和接入进度，支持授权录入、轮换、启停与无值审计。
- REQ-02：AI 密钥独立管理 Provider 凭据，按项目、供应商、能力和鉴权模式登记；火山语音的两种鉴权模式互斥。
- REQ-03：AI 角色独立管理助手人设、系统提示词、模型配置和 AI 密钥引用，采用草稿→发布的不可变版本流程。
- REQ-04：现有消费者逐项改从 MySQL 受控读取；对启动级和跨进程凭据制定可执行的切换顺序；未接入不得宣称已统一。
- BR-01：密钥不可通过 UI/API 回看或导出明文、密文、部分值；轮换创建新版本，停用不物理删除历史版本。
- BR-02：AI 角色不能保存密钥正文；选择密钥只引用用途标识。发布角色不自动开启外部 Provider 调用或提升工具权限。
- BR-03：若依用户角色负责管理权限，AI 角色负责 AI 行为，两套角色不混用。已发布角色版本和已启动运行保持版本固定。

| AC | 优先级 | 可观察结果 |
|---|---|---|
| AC-01 | P0 | 菜单中可分别进入三个页面；只有平台密钥权限者不能因此访问 AI 密钥/AI 角色，反之亦然；直访 API 同样拒绝。 |
| AC-02 | P0 | 授权用户录入平台或 AI 密钥后，MySQL 保存密文与元数据；列表、详情、审计、日志、导出和再次打开弹窗均不出现密钥值。加密/写入失败时原生效版本不变。 |
| AC-03 | P0 | 火山语音仅接受 `api-key` 或完整的 `app-id + access-token`；缺项或混用拒绝保存，ASR/TTS 使用同一版本快照。 |
| AC-04 | P0 | AI 角色草稿包含人设、提示词、模型、非秘密参数和 AI 密钥引用；发布后正文不可改，修改须新版本；模型与凭据供应商不匹配时拒绝发布。 |
| AC-05 | P0 | 新任务引用已发布角色版本及配置哈希，旧任务仍可定位原版本；角色停用不篡改已发生运行。若依用户角色权限不会被 AI 角色配置改变。 |
| AC-06 | P0 | 消费者显式切到 MySQL 来源后，缺值、停用、解密失败或数据库不可用均失败关闭，不静默回退环境值；现有真实 Provider 安全开关关闭时配置了密钥也不外呼。 |
| AC-07 | P0 | MySQL 启动凭据与库内密文根密钥保留最小外部自举来源，后台明确说明；其余标记“已接入”的凭据有实际消费者替换及定向验证证据。 |
| AC-08 | P1 | 操作记录可按模块、用途、操作者和时间筛选，含原因与结果，不含任何秘密正文；版本切回/停用均留审计。 |

## 4. 设计

### 4.1 MySQL 存储与自举

平台 MySQL 持有两个密钥模块的共同存储：固定用途绑定表、不可变密文版本表、无值审计表；绑定项含 `kind=PLATFORM/AI`，服务端每条 API 对 kind 和权限同时校验。AI 角色有独立主表与不可变版本表，版本记录人设、提示词、模型、参数、工具和护栏，以及 AI 密钥的稳定引用和配置哈希。业务模块只引用角色版本标识，保留各自运行和业务数据所有权；面试 PostgreSQL 与平台 MySQL 不做跨库外键、JOIN 或事务。

每版密钥用 AES-256-GCM、独立随机 nonce 和包含 kind/用途/版本的 AAD 加密；密文及 key ID 在 MySQL，解密根密钥在独立的部署密钥来源。**MySQL 连接所需最低凭据和解密根密钥不能只存本库**：否则连接/解密前无法取出它们。这是技术自举条件，不是额外的后台业务模块。若未来采用外部 KMS 或实例身份认证，可替换自举来源，而平台密钥页面仍为日常管理入口。数据加密类凭据须保留旧版本解密历史数据，不能只保存“当前值”。

当前 `SysConfig` 列表、详情、导出、公开 configKey 接口和 `toString()` 都会返回参数值，不能用 `sys_config` 存密钥。新服务端接口只返回元数据。若依 `@Log` 默认保存请求和响应；所有含秘密的写接口显式设置 `isSaveRequestData=false`、`isSaveResponseData=false`，另记不含正文的审计。前端不在 localStorage、URL、持久 store 中保存输入。内部解析器只允许登记的固定用途，不开放“传任意 key 名取明文”的 HTTP 接口。

### 4.2 来源切换和版本

用户进一步明确不允许运行时保留两套密钥来源。现有消费者改为只从 MySQL 密钥模块读取；缺值、停用、解密失败或数据库故障均失败关闭，不回退到旧环境变量。主 MySQL 最低连接凭据和密文根密钥是不可避免的自举例外。轮换先写不可变新版本，再原子更新当前版本指针；写入/停用检查行版本。每版同时固定供应商、能力和鉴权模式，恢复历史版本时在服务端解密旧版并以该版元数据创建新的生效版本，不倒拨指针，也不回传明文。需保留旧会话或密文的用途先由服务端复制生效值到固定 previous 用途，再轮换 active；服务端拒绝直接写入或恢复固定 previous 用途，且 active 值变化前必须确认 previous 与旧 active 完全一致。若 previous 仍在生效且内容不同，拒绝覆盖。若需再次轮换或恢复，请先完成旧会话/历史密文处理并停用 previous，再保留当前 active。若依当前 JWT 用途禁止直接停用，以免后台全部失去操作入口。启动期消费者须按顺序重启，目前没有自动热加载；超过一个 previous 版本的历史数据重加密流程仍未实现，第二次轮换数据加密键前必须先解决历史密文依赖。

面试 DeepSeek/火山 adapter 目前在启动时持有值，须改为每次业务调用取生效版本，且一次调用内使用同一快照。AI 角色版本可引用密钥绑定而不能把密钥值写入版本 JSON。角色发布时检查引用存在、供应商/能力匹配及业务配置合法；实际运行仍由各业务的安全开关、权限和预算控制。

### 4.3 AI 角色与既有 Agent

智能选品已有 `fq_agent`、不可变 Agent 版本和管理端页面，其中版本含系统指令、模型和配置。这些是现有业务事实，不能简单复制到新表后让两边同时成为“当前生效角色”。接入顺序：先为既有版本建立稳定映射并保留旧版本只读；新的共享角色版本由 AI 角色模块持有；选品新 Run 逐步改为引用共享角色版本并保存执行快照，已发生 Run 继续引用原业务版本。面试已有配置/Prompt 版本 port，新增解析适配时沿用其不可变引用语义。Aden 的真实工具和 Provider 权限不由角色内容授予，仍按 Aden 自身批准的控制面处理。

### 4.4 权限、故障和恢复

三个模块各设 `list/query/write/activate/audit` 或 `publish` 权限，若依现有角色管理分配；默认不给普通角色新增授权。超级管理员在若依框架中有全权限，需按高权账号管理。第一版权限为全局管理员；如果不同项目的管理员需要互相不可见，还须增加服务端项目作用域 ACL，不能把列表筛选当成隔离。

风险重点：日志泄漏、越权写入、密文错绑、密钥轮换中断、双进程版本分裂、AI 角色发布后配置漂移、业务 Provider 安全开关旁路、根密钥丢失。停止条件为任一 P0 发生；恢复依赖不可变旧版本、显式来源切换、MySQL 密文备份和外部根密钥恢复。恢复前核实旧 Provider 凭据仍有效；“数据库可回滚”不等于 Provider 侧撤销可逆。L3 权限、加密、轮换和恢复决策需要独立于实施者复核。
